Predicting House Prices with Linear Regression¶

Objective: Build and evaluate a linear regression model that predicts a house's sale price from its physical characteristics, and interpret what the model learned.

Dataset: house_prices_practice.csv — 300 houses with 8 structural/quality features and a SalePrice target.

2. Feature Selection Discussion¶

Before building anything, it's worth reasoning about which of the 8 available features are plausible price drivers, based on domain knowledge of real estate:

  • GrLivArea (above-ground living area, sq ft) — almost certainly the single strongest predictor. Bigger livable space is the most direct driver of price in most housing markets.
  • OverallQual (1–10 quality rating) — a composite quality/finish score should track price closely; higher-quality builds command a premium independent of size.
  • TotalBsmtSF (basement square footage) — extra finished/usable space, expected to add value, though typically less than above-ground area.
  • GarageCars (garage capacity) — a practical amenity buyers pay for, and often correlates with overall house size/quality too.
  • FullBath — more bathrooms generally track with larger, more expensive homes.
  • YearBuilt — newer homes can command a premium (modern construction, less deferred maintenance), but this isn't guaranteed — a well-maintained older home in a desirable style can outprice a newer budget build.
  • BedroomAbvGr (bedroom count) — often weaker than expected once GrLivArea is already in the model, since bedroom count and living area are correlated with each other (more bedrooms usually means more square footage, so this feature may add little on its own).
  • LotArea (lot size) — expected to matter less for urban/suburban houses where the house itself, not the land parcel, drives price; can vary a lot by location, which this dataset doesn't capture.

Note on location: the task brief mentions location as an example predictor, but this particular dataset contains no location field (no city, zip code, or neighbourhood column) — so the model below works entirely from structural and quality characteristics. This is called out explicitly rather than silently assumed, since a real production model for this problem would very likely need location data to perform well outside of this one dataset.

Categorical encoding: every column here is already numeric, so there are no categorical features to One-Hot Encode in this dataset. This is confirmed programmatically below rather than assumed.

  • YearBuilt (+$746 per year) has a small positive effect — newer construction adds modest value, all else equal.

11. Bonus: Comparing Against Ridge & Lasso Regularisation¶

Regularised regression (Ridge = L2 penalty, Lasso = L1 penalty) shrinks coefficients to reduce overfitting risk — most useful when features are highly correlated with each other or numerous. With only 7 features and a strong underlying linear signal, we'd expect regularisation to change very little here, but we check rather than assume.

In [16]:
scaler = StandardScaler()
X_train_scaled = scaler.fit_transform(X_train)
X_test_scaled = scaler.transform(X_test)

# Re-fit plain Linear Regression on the SAME scaled features for a fair comparison
lr_scaled = LinearRegression()
lr_scaled.fit(X_train_scaled, y_train)
pred_lr_scaled = lr_scaled.predict(X_test_scaled)

ridge_model = Ridge(alpha=1.0)
ridge_model.fit(X_train_scaled, y_train)
pred_ridge = ridge_model.predict(X_test_scaled)

lasso_model = Lasso(alpha=1.0)
lasso_model.fit(X_train_scaled, y_train)
pred_lasso = lasso_model.predict(X_test_scaled)

def scores(y_true, y_pred):
    return (np.sqrt(mean_squared_error(y_true, y_pred)), r2_score(y_true, y_pred))

results = pd.DataFrame([
    ['Linear Regression', *scores(y_test, pred_lr_scaled)],
    ['Ridge (alpha=1.0)', *scores(y_test, pred_ridge)],
    ['Lasso (alpha=1.0)', *scores(y_test, pred_lasso)],
], columns=['Model', 'RMSE', 'R2 Score']).round(2)

Observation: as expected, Ridge, Lasso, and plain Linear Regression all perform almost identically (R² within 0.001 of each other) on this dataset. This confirms the earlier suspicion — with only 7 features and no severe multicollinearity, there's little overfitting for regularisation to correct, so plain Linear Regression is already close to as good as it gets here. Regularisation would likely matter more on a dataset with many more (or more collinear) features.

12. Conclusion¶

Final model performance: the Linear Regression model achieves an R² of 0.97 and an RMSE of about $12,500 on held-out test data — a strong result driven primarily by GrLivArea, OverallQual, and GarageCars.

Key takeaways:

  1. Living area, overall quality, and garage capacity are the dominant price drivers in this dataset; bedroom count and lot size contribute comparatively little once those are accounted for.
  2. Residuals are randomly distributed with no systematic pattern, meaning a linear model is a reasonable functional form for this data — there's no strong evidence of a non-linear relationship being missed.
  3. Regularisation (Ridge/Lasso) offers no meaningful improvement here, suggesting the plain linear model is not overfitting given the feature set size.
  4. This dataset has no location data — a genuine limitation. A production-grade price model would very likely need neighbourhood/location features to generalise well beyond a single market.
