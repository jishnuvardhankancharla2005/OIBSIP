Wine Quality Prediction — Classification¶

Objective: Train and compare multiple classifiers to predict red wine quality from its physicochemical properties, and determine which is most suitable for deployment.

Dataset: winequality-red.csv — 1,599 red wine samples, 11 physicochemical features (acidity, sugar, chlorides, sulfur dioxide, density, pH, sulphates, alcohol), and an integer quality score from the original UCI Wine Quality dataset.

3. Class Imbalance — Discussion¶

Are certain quality scores underrepresented? Emphatically yes: scores 3 and 8 combined make up only 1.75% of the data (28 out of 1,599 wines), while scores 5 and 6 make up 82.5%. This is a severe imbalance across 6 raw classes.

How does this affect modelling?

  1. Statistically unreliable evaluation for rare classes. With only 10 wines scoring 3 in the entire dataset, an 80/20 split would leave roughly 2 in the test set — far too few to draw any meaningful conclusion about how well a model predicts that class.
  2. Models will default to the majority classes. A classifier trained on 6 raw classes has every statistical incentive to never predict 3 or 8 at all, since doing so barely moves overall accuracy but does risk being wrong.
  3. Accuracy becomes a misleading metric on its own — a model could score ~80%+ accuracy by only ever predicting 5 or 6, while being completely unable to identify genuinely poor or excellent wines, which are arguably the most business-relevant cases to catch.

This motivates the binning decision in Section 4.

4. Feature Engineering: Binning Quality into 3 Classes¶

Decision: bin the 6 raw scores into 3 ordinal groups — Low (3-4), Medium (5-6), High (7-8) — rather than predicting the raw 3-8 score directly, and rather than collapsing all the way to a binary good/bad split.

Why 3 classes instead of 6: pools the extremely sparse scores (3, 4, 8) with their nearest neighbour so every class has enough samples for the model to learn from and for evaluation to be statistically meaningful.

Why 3 classes instead of binary (e.g. good ≥ 7 vs. bad < 7): a binary split would still leave the positive ("good") class at only 13.6% of the data, and would also throw away the useful distinction between a merely mediocre wine and a genuinely poor one — collapsing Low into the same "bad" bucket as Medium loses information that a business user (e.g. a producer trying to catch defective batches) would likely still want. Three ordinal classes keep that structure while still relieving the worst of the sparsity problem.

Trade-off, stated plainly: even after binning, Low (63 wines, 3.9%) is still a small minority next to Medium (1,319 wines, 82.5%) — this doesn't eliminate the imbalance, it only makes it survivable for modelling. The results in Section 7 show this trade-off did not fully resolve the problem for the rarest class.

6. Training Three Classifiers¶

  • Random Forest — an ensemble of decision trees; handles non-linear relationships and feature interactions well, and gives us feature importances "for free."
  • Stochastic Gradient Descent (SGD) Classifier — a fast linear classifier trained via gradient descent; a good lightweight baseline.
  • Support Vector Classifier (SVC) — finds the maximum-margin boundary between classes, using an RBF kernel here to capture non-linear boundaries.

from sklearn.metrics import precision_recall_fscore_support

def summarize(name, y_true, y_pred):
    acc = accuracy_score(y_true, y_pred)
    p, r, f1, _ = precision_recall_fscore_support(y_true, y_pred, average='macro', zero_division=0)
    pw, rw, f1w, _ = precision_recall_fscore_support(y_true, y_pred, average='weighted', zero_division=0)
    return {'Model': name, 'Accuracy': acc, 'Macro F1': f1, 'Weighted F1': f1w, 'Macro Recall': r}

10. Conclusion¶

Which model is most suitable for deployment, and why? Random Forest — it wins on every metric in Section 9 (accuracy, macro F1, weighted F1, macro recall), handles the non-linear relationships between chemical features better than the linear SGD classifier, and — critically for a deployment scenario — provides interpretable feature importances (Section 8) that a wine producer could actually act on (e.g. "watch alcohol content and volatile acidity closely"), which neither SGD nor SVC offer as directly.

The honest caveat: none of the three models, including Random Forest, can currently identify a Low-quality wine at all (0% recall on that class, even after class-weighting). Before this model is deployed for any use case where catching low-quality wine matters, the priority isn't a better algorithm — it's more Low-quality training examples. With only ~50 such wines in the entire training set, no amount of model tuning is likely to fix this; the bottleneck is data, not modelling choice. As deployed today, this model should be described honestly as "a Medium vs. High quality classifier with a Low-quality blind spot," not as a general-purpose quality predictor.
